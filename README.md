# amnezia-doctor

Детерминированная диагностика подключения к **Amnezia** с Mac: AmneziaWG, WireGuard
и контейнеры Amnezia в Docker. Одна команда проверяет Mac, сеть до сервера и сам сервер по SSH,
а на выходе даёт архив с отчётом, рекомендациями и сырыми логами, готовыми для анализа в LLM.

## Запуск на любом Mac

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ZhdanDesign/amnezia-doctor/main/run.sh) root@IP_СЕРВЕРА
```

Команда скачивает пакет скриптов во временную папку, запускает проверку и удаляет пакет.
Ничего не устанавливает. Пароль SSH, если нужен, вводится один раз.

С ключом и клиентским конфигом для сверки с сервером:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ZhdanDesign/amnezia-doctor/main/run.sh) \
  -i ~/.ssh/id_ed25519 -c ~/Downloads/mac.conf root@IP_СЕРВЕРА
```

`-c` принимает файл `.conf` или текстовый файл с ключом `vpn://…` из приложения Amnezia.

Результат появится на рабочем столе: папка `amnezia-doctor_<сервер>_<время>` и zip-архив рядом.
Пришлите **архив**.

## Параметры

| | |
|---|---|
| `-p ПОРТ` | порт SSH, по умолчанию 22 |
| `-i КЛЮЧ` | приватный SSH-ключ |
| `-c ФАЙЛ` | клиентский конфиг: `.conf` или ключ `vpn://` |
| `-o ПАПКА` | куда сложить результат, по умолчанию `~/Desktop` |
| `--no-probe` | не проверять доставку UDP до сервера |
| `--analyze ПАПКА` | пересобрать отчёт из готового `facts.txt`, без сети |

Закрепить версию: `AMNEZIA_DOCTOR_REF=v1.0.0 bash <(curl -fsSL …/run.sh) root@IP`.

## Что проверяется

Проверки идут в порядке причинности. Вердикт — первая `FAIL`, при её отсутствии первая `WARN`.

**Сеть** — `NET01` IP не определяется · `NET02` сервер недоступен (нет ни ping, ни TCP) ·
`NET03` ping закрыт, TCP открыт · `NET04` SSH-порт не отвечает · `NET05` доступен.

**SSH** — `SSH01` вход не удался (разбирает причину: ключ, смена ключа хоста после
переустановки, обрыв) · `SSH02` вход выполнен.

**Сервер** — `SRV00` сбор не завершился · `SRV01` нет root/sudo · `SRV02` ждёт перезагрузки ·
`SRV03` мало памяти · `SRV04` мало диска · `SRV05` расхождение часов с Mac · `SRV06` нет NTP ·
`SRV07` нет выхода в интернет · `SRV08` нет DNS · `SRV09` NAT у хостера.

**VPN** — `VPN01` VPN не найден · `VPN02` Docker не запущен · `VPN03` контейнеры Amnezia
остановлены · `VPN04` контейнер перезапускается · `VPN05` интерфейс работает ·
`VPN06` нет клиентов · `VPN07` сейчас никто не подключён.

**Файрвол** — `FW01` выключен IP-форвардинг · `FW02` нет NAT (MASQUERADE) · `FW03` ufw не пропускает
порт VPN · `FW04` политика INPUT DROP без разрешения порта · `FW05` ваш IP забанен fail2ban ·
`FW06` fail2ban банит других.

**Доставка пакетов** — сервер запускает `tcpdump`, Mac отправляет на каждый UDP-порт VPN пять
помеченных пакетов. Так видно, режет ли UDP провайдер или DPI.
`PRB00` пропущено (нет tcpdump или root) · `PRB01` UDP не доходит · `PRB02` частичные потери ·
`PRB03` доходит · `PRB04` TCP-порт закрыт снаружи · `PRB05` проба не удалась.

**Клиентский конфиг** (с `-c`) — `CFG01` не разбирается · `CFG02` другой адрес сервера ·
`CFG03` порт не слушается · `CFG04` чужой ключ сервера (конфиг от прошлой установки) ·
`CFG05` не совпадают параметры обфускации `Jc/Jmin/Jmax/S1–S4/H1–H4/I1–I5` ·
`CFG06` пир удалён на сервере · `CFG07` ни разу не подключался · `CFG08` подключался давно ·
`CFG09` на связи · `CFG10` MTU · `CFG11` утечка IPv6 · `CFG12` нет DNS.

**Mac** — `CLI01` нет интернета · `CLI02` нет DNS · `CLI03` запущены другие VPN/прокси ·
`CLI04` системный прокси · `CLI05` нет приложения Amnezia · `CLI06` трафик к серверу идёт
через VPN-интерфейс · `CLI07` ошибки в логах Amnezia · `CLI08` Mac выходит в сеть через этот сервер.

**Безопасность** — `SEC01` вход root по паролю.

## Что в архиве

```
report.md       отчёт для человека: вердикт, находки, что сделать, все факты
report.json     то же в машинном виде — главный файл для LLM
LLM_PROMPT.md   готовый промпт для анализа в сторонней LLM
facts.txt       все факты KEY=VALUE — из них отчёт пересобирается командой --analyze
findings.tsv    находки построчно
raw/client/     маршруты, DNS, прокси, логи приложения Amnezia на Mac
raw/server/     docker, awg/wg, iptables, ufw, fail2ban, journal, dmesg
raw/probe_capture.txt  что tcpdump увидел на сервере во время пробы
```

Анализ в LLM: откройте `LLM_PROMPT.md`, скопируйте текст и приложите `report.json`.

## Гарантии

**Сервер только читается.** Пробник ничего не устанавливает, не перезапускает и не меняет.
Если нет `tcpdump` — проверка доставки пропускается с подсказкой, а не ставит его сама.

**Секреты не попадают в отчёт.** Приватные ключи, PSK, пароли, токены и ключи `vpn://`
вырезаются ещё на сервере, до отправки на Mac. Из клиентского конфига берётся только факт
наличия приватного ключа. Адреса чужих клиентов маскируются до `a.b.c.x`, MAC-адреса Mac — тоже.
В отчёте остаются IP сервера и публичный IP вашего Mac: без них диагностика невозможна.

**Детерминированность.** Набор проверок, их порядок, пороги и тексты рекомендаций фиксированы,
случайности и LLM внутри нет. Одинаковый `facts.txt` даёт байт-в-байт одинаковые `report.md`
и `report.json` — это проверяют тесты.

**Совместимость.** Работает на стоковом macOS с `/bin/bash` 3.2: нужны только perl, curl, nc,
ssh и zip, которые есть в системе. На сервере — bash и стандартные утилиты Linux.
