# amnezia-doctor

Почему на **этом** Mac не работает Amnezia — когда с телефона или другого компьютера всё работает.
Главный случай: «VPN подключился, а интернета нет».

## Запуск

Включите VPN в Amnezia, откройте Терминал и вставьте одну строку:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ZhdanDesign/amnezia-doctor/main/run.sh)
```

Ничего не спрашивает и ничего не устанавливает. Настройки и ключи Amnezia не читает. Работает около 15 секунд.
В конце — большая цветная плашка: ✅ зелёная «ВСЁ РАБОТАЕТ», ⚠️ жёлтая «РАБОТАЕТ, НО ЕСТЬ ЗАМЕЧАНИЯ»
или ❌ красная «НЕ РАБОТАЕТ» с главной причиной, 👉 инструкцией и списком всех проверок.

Сразу после неё — ссылки на папку и отчёт (⌘ Cmd + клик) и меню «Куда отправить архив?»:

| | |
|---|---|
| 💬 Telegram | откроется Telegram, архив уже в буфере обмена — выберите чат и нажмите ⌘V |
| ✉️ Почта | новое письмо в Mail с архивом во вложении |
| 📋 Скопировать архив | ⌘V в любом мессенджере вставит архив как файл (WhatsApp, Telegram, Slack…) |
| 📂 Показать в Finder | архив выделен — перетащите куда нужно |

Пункты появляются, только если приложение установлено. Enter — ничего не делать.
Само сообщение отправляет человек: скрипт только готовит его.
На рабочем столе появится zip-архив — его и пришлите.

Чтобы заодно проверить сервер, добавьте его IP:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ZhdanDesign/amnezia-doctor/main/run.sh) 203.0.113.10
```

Сервер проверяется по SSH ключом из `~/.ssh`. Пароль не спрашивается: если ключа нет, проверка
сервера пропускается, а проверка Mac выполняется полностью.

## Как он находит причину

Скрипт смотрит на VPN со стороны macOS: какой туннель поднят, куда идут маршруты, сколько
байт ушло на сервер и сколько пришло обратно. Потом прогоняет тестовый трафик — ping, HTTPS по IP,
DNS, большие пакеты, загрузку 1 МБ — и сравнивает счётчики до и после. По тому, на каком шаге
теряются пакеты, ставится диагноз:

| Что видно | Диагноз |
|---|---|
| на сервер уходит, обратно ничего | провайдер этой сети режет VPN, или сервер не отвечает |
| сервер отвечает, но туннель ничего не принимает | ключ подключения устарел или не совпадает с сервером |
| служебные ответы есть, ответов из интернета нет | сервер не выпускает трафик в интернет (NAT) |
| по IP работает, по именам нет | DNS |
| мелкие пакеты проходят, крупные нет | MTU — часть сайтов не грузится |
| интернет идёт мимо туннеля | маршруты перехватил другой VPN |

У каждой находки есть простая инструкция: что нажать в Amnezia или в настройках Mac.

## Что проверяется на Mac

- **Amnezia**: установлена ли, запущена ли, подключён ли VPN, какой движок (AmneziaWG, WireGuard, XRay, OpenVPN)
- **Туннель**: интерфейс, адрес, MTU, весь ли трафик идёт через VPN, сколько сайтов в обход
- **Трафик**: доходят ли пакеты до сервера и обратно — по счётчикам до и после теста
- **Интернет через VPN**: ping и HTTPS по IP, точка выхода в сеть (IP и страна)
- **DNS**: системный и напрямую через 1.1.1.1
- **MTU**: проходят ли пакеты полного размера, не обрывается ли загрузка 1 МБ
- **Скорость** через VPN
- **Kill switch**: блокируется ли интернет мимо VPN
- **IPv6**: не идёт ли мимо туннеля
- **Помехи**: другие VPN (Happ, v2ray, Outline, Clash и др.), второй туннель, системный прокси,
  сторонние файрволы (LuLu, Little Snitch и др.)
- **Логи** Amnezia

## Что проверяется с IP сервера

- **Сеть**: доступность сервера, открыт ли SSH. Если путь к серверу идёт через сломанный туннель,
  об этом прямо сказано, а не выдаётся ложное «сервер недоступен».
- **Доставка UDP**: сервер ловит `tcpdump`-ом пять помеченных пакетов с Mac — так видно, режет ли
  провайдер этой сети VPN-трафик. Нужен `tcpdump` на сервере; скрипт его не ставит.
- **Сервер**: память, диск, перезагрузка, время, выход в интернет; интерфейсы AmneziaWG и
  WireGuard и их клиенты; контейнеры Amnezia в Docker; IP-форвардинг, NAT, ufw/iptables, fail2ban.

## Что в архиве

```
report.md       отчёт для человека: вердикт, находки, что сделать, все факты
report.json     то же в машинном виде — главный файл для LLM
LLM_PROMPT.md   готовый промпт для анализа в сторонней LLM
facts.txt       все факты KEY=VALUE — из них отчёт пересобирается командой --analyze
findings.tsv    находки построчно
raw/client/     маршруты, DNS, прокси, логи приложения Amnezia на Mac
raw/server/     docker, awg/wg, iptables, ufw, fail2ban, journal, dmesg
raw/probe_capture.txt  что tcpdump увидел на сервере во время пробы
```

Анализ в LLM: откройте `LLM_PROMPT.md`, скопируйте текст и приложите `report.json`.

## Гарантии

**Настройки и ключи Amnezia не читаются.** Всё видно со стороны macOS: интерфейсы, маршруты, счётчики.

**Сервер только читается.** Пробник ничего не устанавливает, не перезапускает и не меняет.
Если нет `tcpdump` — проверка доставки пропускается с подсказкой, а не ставит его сама.

**Секреты не попадают в отчёт.** Приватные ключи, PSK, пароли, токены и ключи `vpn://`
вырезаются ещё на сервере, до отправки на Mac. Из клиентского конфига берётся только факт
наличия приватного ключа. Адреса чужих клиентов маскируются до `a.b.c.x`, MAC-адреса Mac — тоже.
В отчёте остаются IP сервера и публичный IP вашего Mac: без них диагностика невозможна.

**Детерминированность.** Набор проверок, их порядок, пороги и тексты рекомендаций фиксированы,
случайности и LLM внутри нет. Одинаковый `facts.txt` даёт байт-в-байт одинаковые `report.md`
и `report.json` — это проверяют тесты.

**Совместимость.** Работает на стоковом macOS с `/bin/bash` 3.2, без sudo: нужны только perl, curl,
nc, ssh и zip, которые есть в системе. На сервере — bash и стандартные утилиты Linux.

## Параметры

| | |
|---|---|
| `IP` | проверить ещё и сервер |
| `-p ПОРТ` | порт SSH сервера, по умолчанию 22 |
| `-i КЛЮЧ` | нестандартный SSH-ключ |
| `-c ФАЙЛ` | сверить с сервером конфиг клиента (`.conf` или ключ `vpn://`) — для администратора |
| `-o ПАПКА` | куда сложить результат, по умолчанию `~/Desktop` |
| `--no-probe` | не проверять доставку UDP |
| `--no-share` | не показывать меню отправки архива |
| `--analyze ПАПКА` | пересобрать отчёт из готового `facts.txt` |

Закрепить версию: `AMNEZIA_DOCTOR_REF=v1.4.1 bash <(curl -fsSL …/run.sh)`.
